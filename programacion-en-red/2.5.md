# Tema 5. Sockets

Un **socket** es cada uno de los extremos de una comunicación a través de una red. Para que haya comunicación existirá un socket en cada lado de la línea de comunicación (en cada host). Cada socket tiene una dirección, que es la combinación de una dirección IP y un puerto.

Existen varios tipos de sockets:

- **Datagram sockets** (sockets no orientados a conexión): usan el protocolo UDP.
- **Stream sockets** (sockets orientados a conexión): usan el protocolo TCP.
- **Raw sockets**: trabajan a nivel IP. Se utilizan en routers y otros dispositivos de red.

Como son de tipos distintos, pueden coexistir dos sockets de distinto tipo en el mismo puerto.

## Sockets en cliente y en servidor

Un **servidor** es un proceso que, al arrancar, crea un socket que se pone a escuchar las posibles conexiones de los clientes para ofrecerles un servicio.

**Servidor TCP**: puede atender a varios clientes simultáneamente creando un proceso o hilo para cada uno y estableciendo una conexión TCP entre ese proceso/hilo y el cliente. Para cada conexión se crea un socket dedicado en el servidor, formando un circuito virtual o sesión TCP con el socket del cliente, es decir, un flujo (*stream*) de bytes full dúplex.

El servidor puede tener varios sockets TCP con la misma IP y puerto local, cada uno en su proceso/hilo atendiendo a su cliente. El sistema operativo los trata como sockets distintos porque no coincide el par de direcciones local/remota: aunque las direcciones locales sean iguales, cambian las remotas. Lo que identifica a un socket TCP es el par de direcciones en su conjunto.

**Servidor UDP**: un socket UDP no puede establecer una conexión, por lo que no crea un proceso/hilo por cliente. El mismo proceso gestiona secuencialmente los paquetes que llegan de todos los clientes a través del mismo socket. Por eso los sockets UDP se identifican únicamente por su dirección local, aunque cada mensaje que llega incluye su propia dirección de origen.

El puerto UDP funciona como una única cola de mensajes que recibe todos los datagramas destinados al programa. Por ello puede recibir mensajes de varios emisores a la vez y admite tanto la comunicación punto a punto como de un punto a varios.

Los puertos TCP son distintos de los UDP y solo admiten comunicación punto a punto, ya que las conexiones TCP se identifican mediante dos pares IP:puerto (los de los dos hosts conectados).

# API de `java.net` (nivel de transporte)

## Clases `SocketAddress` e `InetSocketAddress`

`SocketAddress` es una clase abstracta que representa una dirección de socket sin ningún protocolo en particular, y debe heredarse para implementar uno concreto.

`InetSocketAddress` hereda de `SocketAddress` y representa una dirección de socket IP: una **dirección IP + un número de puerto** (0-65535).

```java
public InetSocketAddress(int port)
```
Crea una dirección de socket en todos los interfaces de la máquina con el puerto especificado.

```java
public InetSocketAddress(InetAddress addr, int port)
public InetSocketAddress(String hostname, int port)
```
Crean una dirección de socket con una dirección IP o un nombre de host y un puerto.

## Proxy

Si nuestra organización dispone de un proxy, puede ser necesario especificarlo en nuestras aplicaciones. Hay dos formas de hacerlo.

### Propiedades de la JVM

Se establecen con `System.setProperty`, asignando los pares propiedad-valor adecuados al protocolo con el que se vaya a trabajar. Su mayor inconveniente es que afecta a **todas** las conexiones de ese protocolo en la máquina virtual.

| Protocolo | Propiedades |
|---|---|
| HTTP | `http.proxyHost`, `http.proxyPort`, `http.nonProxyHosts` |
| HTTPS | `https.proxyHost`, `https.proxyPort` |
| FTP | `ftp.proxyHost`, `ftp.proxyPort`, `ftp.nonProxyHosts` |
| SOCKS | `socksProxyHost`, `socksProxyPort` |

```java
System.setProperty("http.proxyHost", "URLProxyMiEmpresa");
System.setProperty("http.proxyPort", "8080");
```

### Clase `Proxy`

```java
public Proxy(Proxy.Type type, SocketAddress sa)
```

Se especifica el tipo y la dirección del proxy. `Proxy.Type` puede ser:

- `Proxy.Type.DIRECT`: conexión directa o ausencia de proxy. También se puede usar la constante `Proxy.NO_PROXY` al pasar el proxy a un método.
- `Proxy.Type.HTTP`: proxy para protocolos de alto nivel como HTTP o FTP.
- `Proxy.Type.SOCKS`: proxy SOCKS. SOCKS es un protocolo que permite a las aplicaciones cliente-servidor usar los servicios de un firewall de manera transparente.

```java
Proxy miProxy = new Proxy(Proxy.Type.HTTP, new InetSocketAddress("URLProxyMiEmpresa", 8080));
```

## Clases `Socket` / `ServerSocket` (TCP) y `DatagramSocket` (UDP)

La elección entre streams (TCP) o datagramas (UDP) depende de la naturaleza de la aplicación, aunque debería usarse TCP salvo que el uso de UDP sea claramente preferible.

Para una aplicación orientada a conexión se utilizan las clases `Socket` y `ServerSocket`. El `ServerSocket` se usa únicamente para esperar la llegada de conexiones de los clientes; cuando llega una, crea un `Socket` para intercambiar información con el socket del cliente.

En una aplicación basada en UDP no hay que esperar conexiones y se utiliza únicamente `DatagramSocket` (*esta clase no la veremos en detalle en este capítulo*)

### Clase `Socket` (TCP)

Además del constructor por defecto existen los siguientes:

```java
public Socket(InetAddress address, int port) throws IOException
public Socket(String host, int port) throws IOException, UnknownHostException
```
Crean un socket TCP y lo conectan a la dirección/host y puerto especificados.

```java
public Socket(InetAddress address, int port, InetAddress localAddr, int localPort) throws IOException
public Socket(String host, int port, InetAddress localAddr, int localPort) throws IOException
```
Crean un socket, lo enlazan (`bind()`) a la dirección local y puerto indicados y lo conectan al destino. Es útil cuando la máquina tiene varias direcciones IP.

```java
public Socket(Proxy proxy)
```
Crea un socket **no conectado** que usará el proxy especificado.

### Métodos principales

| Método | Descripción |
|---|---|
| `InetAddress getInetAddress()` | Dirección remota a la que está conectado. |
| `InetAddress getLocalAddress()` | Dirección local a la que está enlazado. |
| `int getPort()` | Puerto remoto al que está conectado. |
| `int getLocalPort()` | Puerto local al que está unido. |
| `InputStream getInputStream() throws IOException` | Flujo para recibir información. |
| `OutputStream getOutputStream() throws IOException` | Flujo para enviar información. |
| `void close() throws IOException` | Cierra el socket. |

`close()` cierra también sus `InputStream` y `OutputStream`. Si en ese momento algún hilo está bloqueado sobre este socket, se lanzará una `SocketException`. Una vez cerrado, el socket ya no está disponible (no se puede volver a conectar ni enlazar); si es necesario, hay que crear uno nuevo.

## Clase `ServerSocket` (TCP)

Sirve para esperar, escuchando en un puerto determinado, las peticiones de los clientes.

### Constructores

Además del constructor por defecto:

```java
public ServerSocket(int port) throws IOException
```
Crea un socket de servidor que espera peticiones en el puerto especificado. Si se pasa `0`, se usa cualquier puerto libre.

```java
public ServerSocket(int port, int backlog) throws IOException
```
Como el anterior, pero indicando el tamaño máximo de la cola de peticiones de conexión. Si llega una petición y la cola está llena, la conexión es rechazada.

```java
public ServerSocket(int port, int backlog, InetAddress bindAddr) throws IOException
```
Como el anterior, pero indicando también la dirección a la que enlazarse. Es útil cuando el servidor tiene varias direcciones y queremos que acepte peticiones solo por una de ellas. Si `bindAddr` es `null`, aceptará conexiones por cualquier dirección local.

### Métodos principales

| Método | Descripción |
|---|---|
| `Socket accept() throws IOException` | Espera una conexión (bloquea el programa). Cuando entra un cliente, la acepta y devuelve un nuevo `Socket` para comunicarse con él. |
| `InetAddress getInetAddress()` | Dirección local del socket de servidor. |
| `int getLocalPort()` | Puerto en el que está escuchando. |
| `void close() throws IOException` | Cierra el socket de servidor. |

## Clase `DatagramSocket` (UDP)

Los sockets UDP se utilizan menos que los TCP por sus características, pero son interesantes para aplicaciones que requieren velocidad y no necesitan gran fiabilidad en la transmisión. UDP no establece una conexión previa entre cliente y servidor, por lo que cuando uno envía datos al otro no puede saber si realmente llegan ni, en caso de que lleguen, si lo hacen en orden.

Muchos firewalls y routers están configurados para bloquear el tráfico UDP. Si hay problemas de conectividad, puede ser necesario hablar con el administrador del sistema.

### Constructores

Además del constructor por defecto (que enlaza el socket a cualquier puerto libre):

```java
public DatagramSocket(int port, InetAddress laddr) throws SocketException
```
Crea el socket UDP enlazado a la dirección y el puerto locales indicados. Si la dirección IP es `0.0.0.0` (*wildcard*), el socket se enlaza a todas las interfaces o a la que elija el kernel.

```java
public DatagramSocket(int port) throws SocketException
```
Crea el socket UDP y lo enlaza al puerto local indicado y, como en el caso anterior, a todas las interfaces o a la que elija el kernel.

### DatagramPacket

Para enviar o recibir paquetes UDP (datagramas) primero hay que crear objetos de la clase `DatagramPacket` con alguno de estos constructores:

```java
public DatagramPacket(byte[] buf, int length)
public DatagramPacket(byte[] buf, int offset, int length)
public DatagramPacket(byte[] buf, int length, InetAddress address, int port)
public DatagramPacket(byte[] buf, int length, SocketAddress address)
public DatagramPacket(byte[] buf, int offset, int length, InetAddress address, int port)
public DatagramPacket(byte[] buf, int offset, int length, SocketAddress address)
```

- Los dos primeros no indican destino, así que se usan para **recibir**.
- Los demás incluyen la dirección de destino (IP y puerto), así que se usan para **enviar**.
- `offset` indica a partir de qué posición del array `buf` se leen o escriben los datos, y `length` cuántos bytes.

### Enviar un paquete

```java
public void send(DatagramPacket p) throws IOException
```
Envía un datagrama. El `DatagramPacket` incluye los datos a enviar, su longitud y la IP:puerto del destino.
